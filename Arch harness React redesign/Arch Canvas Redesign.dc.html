3Internals live in a component canvas dialog, not on the main canvas
The change
The system canvas never reflows. Click a component → a component canvas opens over it: its own small infinite canvas with its own pan, zoom and fit, showing that component's internal data flow. Close it and the system graph is exactly where you left it. Supersedes the in-place frame in 2a.
Why it's better here
Node positions are user-owned, so growing a node would shove hand-placed neighbours. A dialog also gives internals their own zoom level — module graphs need much more room than a node's footprint — and one shell serves every facet kind (3c).
Depth inside the dialog
L2 stays in the same dialog — pricing opens as a nested step chain (3b) with a breadcrumb back to L1, so you never lose your place.

1Three directions for the React canvas rebuild
What I'm assuming
  • The harness state stays the source of truth; the canvas is a live projection of it, not a drawing file.
  • User edits (move, rename, responsibility) apply optimistically, then POST as tool-equivalent mutations — a failed POST rolls the node back with an inline notice.
  • Node positions are client-owned and persisted per session; the agent never moves a node you placed. Auto-layout runs only on Tidy up.
  • Annotations and sticky notes are canvas-only — never part of the handoff bundle.
Stack I'd recommend
Vite + React + TS with React Flow for the graph (nodes are typed React components, so a node is the arch-state contract sheet), plus roughjs for the sketch treatment in 1b and a small tldraw-style freehand layer for annotations. Excalidraw-the-package renders beautifully but owns its own document model — fighting it to stay in sync with ArchState costs more than borrowing its look.
